# СнабПро — система управления закупками для производства

СнабПро помогает производственному предприятию вести справочник материалов и поставщиков, формировать закупки, отправлять запросы на коммерческие предложения, собирать ответы по почте и сравнивать полную стоимость поставки.

## Архитектура

- **Frontend:** статический сайт в каталоге `public`, публикация через GitHub Pages.
- **Backend:** Supabase Auth, Postgres, Storage и Edge Functions. SQL-изменения находятся в `supabase/migrations/`, исходники серверных функций — в `supabase/functions/`.
- **Почта:** Gmail OAuth; refresh-токены хранятся в зашифрованном виде в Supabase.
- **Файлы КП:** приватный Storage bucket `quote-documents`.
- **Изоляция данных:** данные предприятий разделены по `company_id`; таблицы защищены RLS.

## Реализовано

- Регистрация и вход, создание предприятия и выбор рабочего пространства.
- Облачное хранение материалов, папок, поставщиков, закупок и позиций закупки.
- Черновики запросов поставщикам сохраняются в базе предприятия и восстанавливаются после повторного входа.
- Подключение Gmail, отправка писем с подтверждением пользователя и синхронизация входящих сообщений.
- Фоновая проверка Gmail каждые 10 минут через Supabase Cron; новые письма сохраняются в `supplier_email_messages`.
- Сопоставление входящих писем с поставщиками и закупками по адресу отправителя и токену в теме письма.
- Извлечение текстового содержимого из PDF/XLS/XLSX-вложений и создание карточки документа для ручной проверки. Сканированные PDF без текстового слоя пока не проходят OCR.
- Проверка КП человеком перед добавлением в сравнение.
- Ручное добавление КП с сохранением в базе предприятия через транзакционную RPC-функцию.
- Сравнение цены, количества и доставки; общая доставка распределяется между позициями пропорционально стоимости товаров.
- Динамические показатели экономии, отчёт руководителю и история сохранённых КП.
- Поиск по собственной базе поставщиков с фильтрами по категории и региону.
- Ролевая проверка для подключения Gmail, отправки писем и добавления КП.

## AI и расходы

Фоновый мониторинг входящих писем сейчас использует Gmail API и локальные правила извлечения полей. **Внешние AI API-вызовы не выполняются**, поэтому за AI-разбор писем сейчас нет дополнительных расходов. Полноценное AI-извлечение и OCR можно подключить отдельно после выбора провайдера, серверного API-ключа и лимита расходов. Ключи нельзя помещать во frontend или GitHub.

## Пока не подключено

- Внешний каталог и поиск новых поставщиков по всему рынку.
- AI-разбор сложных писем и документов, OCR сканированных PDF.
- Оплата подписки и автоматическое управление тарифами.
- Полноценный аудит действий, резервное копирование и клиентские SLA.

## Серверные настройки

Для Gmail Edge Functions используются секреты Supabase:
- `GOOGLE_CLIENT_ID`
- `GOOGLE_CLIENT_SECRET`
- `GMAIL_TOKEN_ENCRYPTION_KEY` — не менее 32 символов

Supabase автоматически предоставляет Edge Functions служебные переменные проекта. Секрет фонового мониторинга хранится в Supabase Vault; расписание выполняется через `pg_cron` и `pg_net`.

## Проверки перед запуском с клиентами

1. Проверить регистрацию, вход и изоляцию двух предприятий.
2. Проверить подключение Gmail и отправку тестового письма на контролируемый адрес.
3. Ответить на письмо с другого ящика и проверить фоновую синхронизацию.
4. Проверить PDF/XLSX-вложения, ручную проверку и сохранение КП.
5. Проверить сравнение, распределение доставки, отчёт и историю цен.
6. Проверить права ролей, мобильную версию и восстановление данных после повторного входа.

GitHub Actions запускает `node --check` для frontend JavaScript перед каждой публикацией GitHub Pages.
