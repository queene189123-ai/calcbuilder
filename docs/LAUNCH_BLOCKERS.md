# СнабПро — что осталось до публичного запуска

Это не блокирует работу текущего пилотного MVP, но должно быть закрыто до массового подключения клиентов.

| Пункт | Статус | Что требуется |
|---|---|---|
| Основные закупки, поставщики, заявки и сохранение данных | Готово к финальной проверке | Проверить владельцем в браузере |
| Gmail OAuth и отправка писем | Подключено, права чтения и отправки выданы | Финально отправить тестовое письмо и получить ответ |
| Фоновый мониторинг Gmail | Работает каждые 10 минут | Проверить реальный ответ поставщика |
| Хранение только релевантной почты | Включено | Содержимое сохраняется только для известных поставщиков или писем с кодом закупки |
| Ручная загрузка КП | Реализована | Проверить PDF/XLSX/CSV на реальном документе |
| Сравнение КП | Реализовано с проверкой одинаковых количества, единицы, валюты и НДС | Проверить на двух реальных предложениях |
| Внешний поиск поставщиков | Только прямые ссылки Google/Яндекс | Для автоматического каталога нужен источник данных или API |
| AI/OCR | Не подключено; внешних AI-вызовов нет | Решить, нужен ли платный AI/OCR и какой бюджет допустим |
| Оплата и подписки | Не подключены | Выбрать платёжного провайдера и открыть аккаунт |
| Политика конфиденциальности и условия | Черновики готовы в docs/legal/ | Заполнить реквизиты оператора и проверить с юристом |
| Google OAuth для клиентов | Текущий Gmail уже подключён | Опубликовать/верифицировать consent screen и указать публичную privacy policy |
| Изоляция внутренних Gmail-таблиц | Готово: права `anon`/`authenticated` закрыты, добавлены 6 deny-all RLS-политик; доступ service role сохранён | Повторно проверить после любых изменений схемы |
| Привилегированные RPC | Готово: реализации перенесены в `private`, публичные RPC — `SECURITY INVOKER`; `anon` закрыт. Проверены тестовыми вызовами в транзакции с откатом | Повторить аудит при изменении RPC |
| Leaked-password protection Supabase | Не включено | Включить настройку в Supabase Dashboard перед публичной регистрацией |
| Развёртывание чистой БД из GitHub | Не подтверждено: девять исходных миграций 4–5 ноября отсутствуют в истории GitHub; точное восстановление невозможно по текущей истории | Подготовить реконструированный baseline по живой схеме и проверить его на отдельном тестовом Supabase-проекте |

## Восстановление схемы БД

Инвентаризация текущей базы и найденная проблема с историей миграций описаны в [supabase/RECOVERY.md](../supabase/RECOVERY.md). Живая база не сбрасывалась и не изменялась в рамках восстановления. Не выдавать реконструированный baseline за оригинальные миграции.

## Данные, которые понадобятся для публичного запуска

- ФИО или полное наименование оператора, ИНН и адрес.
- Контактный email поддержки и запросов по персональным данным.
- Решение по тарифам, оплате и возвратам.
- Решение по AI/OCR: без AI или с отдельным лимитом расходов.
- Решение по автоматическому каталогу поставщиков: платный API или ручной поиск через внешние поисковики.
